# 鲁米线 · 素材策略（先想清楚哪些图非要不可）

> 2026-09-27。起因：Ivy 的判断——「素材会遇到的问题，远远大于 artifact 转换的问题」。
> 结论先说：**鲁米线不照 `ASSET_PROMPTS_RUMI.md` 的 78 张全量生成。** 小游戏的舞台用代码画；
> 讲故事的地方用真实的古画；AI 生成只补最后几张，而且不生成人物。

## 一、生成素材到底会出什么问题（杜甫线、但丁线都踩过）

| 问题 | 在这个项目里的实际表现 | 对鲁米线的风险 |
|---|---|---|
| **同一张脸** | 但丁的鼻子越生成越长（`ASSET_PROMPTS_DANTE.md`「鼻子铁律」）；杜甫默认立绘是空白图，后来补了 15 张分期立绘 | 鲁米要从 12 岁画到 66 岁、16 个姿态——最难的一类 |
| **坐标和图绑死** | 春望找茬换图后 7 个触发点全部重标；连环画换图后 `comic_reveal` 的分格坐标过期（见 `AUDIT.md`） | 摸黑（大象热区）、连环画、地图图钉，每换一次图就要重标一次 |
| **写不出字** | —— | 波斯文 / 阿拉伯文一定是乱码字母，婚约、手稿、地图都会露馅 |
| **考据与宗教分寸** | —— | 13 世纪服饰、不画先知、不把旋转仪式画成舞蹈——每张都要人工审 |
| **风格漂移** | 杜甫线 80+ 张要同一个 seed / style reference 一批跑完 | 分几台电脑、几天跑，风格很难统一 |
| **体积** | 地图单张 4–6 MB，上线前要批量压 webp | 试玩页（单文件 artifact）现在 1.6 MB，塞 30 张图就会过 10 MB |
| **返工** | 剧本改一幕，对应的图就作废 | 鲁米剧本还是 v0.1，至少还会改一轮 |

所以问题不是「能不能生成」，而是**每一张生成图都会带来一串后续工作**（审、抠、压、标坐标、改了剧本再重来）。图越少，这条线越稳。

## 二、三种来源，按这个顺序选

### ① 代码画（首选）——小游戏的舞台

试玩反馈里好玩的几幕，全都是代码画的：水池和墨晕、蜡烛、一百只鸟和七个山谷、湖里的倒影、磨墙、果摊、土墙、信物、送葬队伍。
代码画的好处正好对上第一节的每一条：**没有脸要统一、坐标就是数据、没有乱码字、体积几乎为零、剧本改了跟着改。**

适用：所有「玩家要动手」的舞台和道具、人物剪影、地图底图（手绘风的线条和色块）。

### ② 真实的古画（第二选）——讲故事、看图、画作卡

但丁线已经这么做了：《神曲》那几关用的是波提切利、多雷的原作，`src/data/artworks.json` + `ArtworkLabel` 自动挂墙签，画作库里还能点开看大图。
对教育游戏来说，这比 AI 图更有价值——**玩家看到的是真东西，而且是这段历史自己留下的图像。**

鲁米线的候选（⚠️ 全部要先在 Wikimedia Commons / 博物馆开放获取页面**逐张核实授权和出处**，没核实的字段不写，规矩同 `artworks.json` 的 `_note`）：

| 用在 | 候选作品 | 为什么合适 |
|---|---|---|
| 1220 百鸟会议（飞完之后的画作卡） | 哈比布拉《百鸟会议》，《鸟的语言》抄本插页，约 1600 年，大都会艺术博物馆 | 就是这个故事的古画 |
| 1244 / 1247 沙姆斯 | 奥斯曼时期阿夫拉基《圣徒传》土耳其语译本插图（16 世纪末），画了鲁米与沙姆斯 | 传说本身的图像；正好配「传说」标签 |
| 1258 中国画师与希腊画师：镜中画 | 一幅公有领域的宋代青绿山水（如王希孟《千里江山图》局部） | 镜子里映出的是**真的中国画**——比借用杜甫线的背景图有意义得多 |
| 1258 黑屋里的大象：点灯之后 | 大都会博物馆开放获取里的莫卧儿王朝大象画（印度） | 寓言里的大象正是「从印度带来的」 |
| 1273 婚礼之夜 / 结尾 | 梅夫拉维旋转仪式的历史画作（奥斯曼时期） | 片尾的真实图像 |
| 画作库 / 事件封面 | 科尼亚梅夫拉纳博物馆绿色穹顶、阿拉丁清真寺的照片（CC 授权，需署名） | 地方的真实样子 |

限制：古画的构图是定的，**不能当可交互舞台**（热区坐标会被画面牵着走），只放在「看」的位置：画作卡、揭示后的对照、过场。

### ③ AI 生成（最后）——只补代码画不好、又找不到古画的背景

**不生成人物。** 鲁米本人和所有 NPC 都用代码画的剪影（`figures.jsx`）——这一条去掉了第一节里最大的风险。
主页已经有的三张（`hp_*_rumi`）继续用。

需要生成的只剩几张「有人说话的地方」的背景，而且要画成**低细节、平涂、偏暗**，让代码画的剪影和对话框叠在上面仍然清楚：

| 文件 | 用在 | 说明 |
|---|---|---|
| `pool_courtyard` | 1244 书落水池 | 水池是代码画的，背景只要庭院、拱廊、天光 |
| `konya_street_dusk` | 1244 静下来 | 暗、空、远处一座宣礼塔即可 |
| `samarkand_rooftops` | 1219 贴墙偷听 | 只露出墙上方：屋顶、穹顶、天空 |
| `fruit_market` | 1258 一枚银币 | 路边果摊的背景（果摊本身是代码画的） |
| `damascus_night_bazaar` | 1247 提灯寻人 | 这张是「被照亮的整幅图」，热区坐标跟它走——**出图后要在编辑器重标** |
| `konya_winter` | 1273 婚礼之夜 | 雪、屋顶、城门方向的街 |
| `rumi_general_map` | 大地图 | 不写地名（GameMap 叠加），只画海、河、山 |

合计 **7 张**，清单见 `scripts/assets_manifest_rumi_core.csv`（可直接批跑）。原来的 78 张清单保留作备用。
