# 认知动词 · 这个游戏的设计原则

> 适用于全部人物线（不只但丁）。编排由 `npm run lint:phases` 把关。

## 一句话

> **每一个 interaction 都应该把一个认知动作外化：预测、观察、归类、连接、解释、修正、重建。**

不是「有 16 种小游戏」，而是「每种交互对应一件脑子里正在发生的事」。
这句话应该成为以后写 paper / design rationale 的核心，也是判断一个新 phase 该不该做的唯一标准。

## 问题的诊断（2026-09）

lint 首次跑出来的基线：

| 线 | 读屏 | 浏览 | 认知动作占比 |
|---|---:|---:|---:|
| 杜甫 | 34% | 44% | **18%** |
| 但丁（改造前） | 35% | 25% | **22%** |
| 但丁（第二批之后） | 39% | 28% | **28%** |

八成时间玩家在做同一件事：**点一下，读一段。**

根因不是 phase 类型不够多，而是：**知识先以文字形式进入玩家脑子，interaction 只负责推进 UI。**
`explore`（点 NPC 读对话）和 `transition`（读屏）是同一个动作的两张皮；
`sliding_puzzle`、`escape_game` 这类「花样」跟历史理解无关——它们是包装，不是学习动作。

## 设计原则

```
Do first → see consequence → explain / compare → name the idea
```

先让玩家形成一个 tentative model，再让系统用后续信息修正它。
关键不是「让孩子答错」，是**让错误暴露他当前的心智模型，然后马上和史实并排放着**。

三条推论：

1. **先产出，再讲解。** 任何解释性文本之前，必须有一个让玩家先下判断的动作。
2. **不打 ✓✗。** 玩家的答案要留在屏幕上，和正确答案并列——差额本身是教材。
3. **retrieval 要搬进世界。** 不是事后问「但丁属于哪个党派」，而是在后面的场景里让他
   「把这些人放回你记得的那一边」。从 *retrieve to answer* 变成 *retrieve to act*。

## phase 的分类（lint 用的就是这套）

| 类 | 标记 | 玩家在做什么 | 包含 |
|---|:--:|---|---|
| 读屏 | `·` | 点一下，读一段 | transition, narration, comic_reveal |
| 浏览 | `○` | 找一找，读一段 | explore, map_travel |
| 先判断 | `▲` | 在知道答案前先产出一个判断 | **predict_reveal**, **explain_by_building**, **contrapasso**, poem_compose, forced_choice |
| 辨证据 | `◆` | 在材料里做区分 | **evidence_select**, click_points, exam |
| 改模型 | `★` | 拿自己的答案去撞史实/文本 | inferno_placement, comedy_encounter, **prophecy_paradox** |
| 连成系统 | `✧` | 把散落的东西装成一个系统 | **celestial_spheres**, **trust_game** |
| 排顺序 | `⇅` | 把打乱的东西按因果/时间排回去 | **comic_sort** |
| 过桥 | `◈` | 要动手，但不要求判断（仪式性转场） | echo_portal |
| 手速 | `◇` | 跟理解无关的包装 | sliding_puzzle, escape_game, minigame |

**过桥和手速不计入认知动作占比**——它们好看，但不教东西，别让它们把分数刷上去。

目标：**认知动作占比 ≥ 40%**。

## lint 规则

```
npm run lint:phases          # 全线记分板
npm run lint:phases -- dante  # 单线
```

硬规则（不过 exit 1）
- `H1` 不允许连续 3 个读屏 phase
- `H2` 一个事件不允许「只有读屏 + 点人读字」

软规则（警告 = 待办清单）
- `S1` 每个事件应含 generation　`S2` 应含 evidence　`S3` 应含 revision　`S4` 不建议连续 2 个读屏

## 已实现的新动词

### `predict_reveal` — 先猜，再对照
玩家在事情发生前先预测。提交后左右并列「你猜 / 实际」，**没有对错标记**，
再演出后果。分数奖励「敢下判断」这个动作本身——猜对猜错一样多，
否则玩家会退回到揣摩标准答案。
> 替换：大量作为伪选择的 `forced_choice`。素材成本：纯文本。

### `evidence_select` — 给一个判断，挑出支持它的材料
干扰项的设计要点：**不要放假的，要放「真的但不相干」**。
要练的是「真实 ≠ 支持结论」，不是辨真假。最好的一条干扰项甚至是
「真实、重要，但对这个判断反而不利」——好的推理要认得出哪些事实对自己不利。
> 替换：`explore` 之后那段替玩家写好的文字总结。素材成本：纯文本。

### `inferno_placement` — 已从 correct/wrong 改成 commit → contrast
提交后玩家的答案留在原地变成 ghost（虚线），但丁的答案在旁边亮起来。
判词从「放对 N/4」改成「你和但丁，N/4 处放到了一起」，
并对每个人显示「你放「炼狱」　但丁放「地狱」」。

### `explain_by_building` — 用零件搭出一句解释
解释 = 摆弄关系，不是打字。玩家把因果块摆进槽位，**底部那句话随着摆放实时长出来**——
他看着自己的解释成形，这才是 self-explanation。多给 1–2 块「真实、重要，但不在这条因果线上」
的零件（教皇、金币），逼他判断什么算因果、什么只是同时发生。
提交后「你写的 / 史家写的」并列。
> 落点：1300 执政官——他做对了公事却毁掉挚友，两年后同一套规矩毁掉他自己；
> 所以《神曲》第一页是一个人在森林里迷路。素材成本：纯文本。

### `contrapasso` — 定一个罚（但丁线招牌机制）
同一组件四档 fading scaffolding：`match`（给罪和罚连线）→ `choose`（三选一）→
`reverse`（给罚反推罪）→ `build`（给零件自己设计）。**已实现 reverse / build。**
build 档没有唯一正解——但丁的写法只是众多可能里的一种，所以提交后是
「你设计的 / 但丁写的」并列，再给罪罚对折图，最后才说出 contrapasso 这个词。
> 顺序是 mechanic → realization → terminology，不是先讲名词再举例。
> 落点：1308 异乡的面包（替掉原来的数字华容道——那个是手速，不教东西）。

### `prophecy_paradox` — 「预言」一件已经发生的事
玩家把三块时间摆到轴上：人物说话的 1300、事情发生的 1302、作者写下的 1310 年代。
摆完自己发现：人物在往前看，作者在往回看，两道目光在 1300 年这一点上对撞。
> 这件事原本是用一段过场文字**告诉**玩家的。现在他自己摆出来。
> 落点：1292 布鲁内托重逢之后（《地狱》XV 里布鲁内托当场预言但丁的流放）。几乎零美术成本。

### `celestial_spheres` — 九重天（《天堂》专用语法）
**这一关整个换了语法。** 三界各有各的动词：

```
地狱   归类   你是什么？        → inferno_placement, contrapasso
炼狱   顺序   什么先，什么后？   → comic_sort
天堂   连接   万物怎么接起来？   → celestial_spheres
```

所以这里**没有对错判定，只有亮不亮**。放对了那一重就点起来、开始转、响一个音，
整个画面亮一档；放错了它只是暗着，随时取回来重放。排序的依据写在题面上——
「越往外转得越快，因为离神越近」——玩家据此推理，不是硬记九个名字。

音是 WebAudio 现合成的（多利亚调式九级上行），不依赖任何音频文件，
并且尊重全站的 🎵 开关（`localStorage.lishiyou_music`）。九重全亮后拉远，
收整条线的旅程。

**关键在于这一关是回款，不是新内容。** 玩家在这里遇到的人都是他早就认识的：
皮卡尔达在月亮天——她是科尔索和福雷塞的妹妹，那两个哥哥玩家刚在 1302 亲手放进
地狱和炼狱；卡恰圭达在火星天——1265 见过他，1302 那句「别人的面包多咸」也是他说的。
多纳蒂家三兄妹正好散在三界。这才是「journey completion」的实义：
不是走完了九关，是发现这九重天里站的全是熟人。

> 落点：1321 拉文纳，替掉原来的「三使徒之考」quiz——那场考试现在是第八重天。
> 素材成本：零。全部是 CSS + SVG + WebAudio。

### `comic_sort` — 把连环画排回故事顺序
炼狱的动词。三界语法本来缺这一块：地狱是归类（你是什么），天堂是连接
（万物怎么接起来），炼狱一直空着。排顺序正是「什么先、什么后」。

**不切图。** 每一格都是同一张长图，用百分比 sprite 公式从里面「取」出来：

```
background-size:     (100/w*100)%  (100/h*100)%
background-position:  (x/(100-w)*100)%  (y/(100-h)*100)%
容器宽高比 = (w × 整图宽高比) / h      ← 漏掉「整图宽高比」这一项，每格都会被拉扁
```

零新文件；长图以后重新分格，改数据就跟着变。公式已用 Playwright 渲染出来的像素
和 PIL 直接裁的同一格逐像素比过：平均差 0.5%，纯重采样噪声。

三档难度（同一个组件，靠 `phase.mode` 切）：
`hinted`（每个空槽下给 ≤12 字的 caption）→ `bare`（不给，纯靠画面推）→
`decoy`（掺 1 格不属于这个故事的，要认出来并丢掉）。

**空槽一律是同一个形状**（4:3），格子的真实比例只在放进去之后才显出来——
空槽照着正确那一格的形状开口，等于把答案印在题面上。

提交后不打 ✗：玩家排的那一行留在原地，排错的描红、排对的描绿，
正确的一行紧挨着排在下面。两行一比就知道差在哪一格。

> 落点：杜甫 759 石壕村（6 格）—— 全线唯一有严格因果链的连环画；
> 但丁 1265 卡恰圭达（5 格）—— 1265 原本是全线唯一还挂硬规则的事件
> （整关没有任何需要玩家先判断的动作），这一关补进去正好把它救回来。
> 岳阳楼、江上旧梦那类意境蒙太奇不要用：排序会变成瞎猜。

**两个坑，记下来免得重踩：**
1. 石壕村那张长图每一格顶部烧着一条深色说明带，还带着序号「1.」「2.」…
   不处理就等于把答案印在牌面上。实测说明带高 47px / 整图 941px ≈ 5.0%，
   六格一致（是固定像素高度，不是固定百分比）。做法是每格 `y += 5.2`、`h -= 5.2`，
   逐格导出肉眼确认过：六格里一个数字、一句说明都看不见。
2. 1265 那张的 `p5_baptism` 在原 `comic_reveal` 里圈的是「抄本正文 + 洗礼」两块，
   拿来当拼图会出一张认不出的牌。已按实测画框重新量过五格
   （竖框在 32.3–33.6 / 66.0–67.6，横框在 0–1.6 / 48.8–51.4，
   底排中间那块是抄本正文，不是画格）。
   **`comic_reveal` 那边的 p5 还是老坐标**，见 docs/AUDIT.md。

### `trust_game` — 放逐循环（可玩的迭代博弈）
结构借自 Nicky Case《The Evolution of Trust》，换成佛罗伦萨真实的那台机器：
两党轮流上台，上台就放逐对方，被放逐的带外援回来，再放逐回去，反复五十年。

四幕：**交手 8 轮 → 猜对方按什么规矩出手 → 让满城跑一遍 → 但丁的转折**。
收益沿用原作那组（+2/+2、−1/+3、0/0），另加一条「城的元气」血条：
两家都在得分而城在流血，这才是这段历史的形状。

两个滑块就是原作那两条结论，换成佛罗伦萨的说法：
**能不能回来**（每场打几轮）和**猜疑**（命令被误传的概率）。

> ⚠️ **文案必须跟模拟对齐，不许照直觉写。** 我第一版把高猜疑区写成「以牙还牙
> 互相报复到底」，干跑 12 次 × 25 代实测是「赶尽杀绝」重新占上风，已按实测改。
> 改动策略、收益或代数之后，重跑一遍再改文案：把 ScenePlayer 里
> `const SPARE` 到 `runCity` 那段抠出来存成 .mjs 就能直接 node 跑。
> 实测（12 次取众数）：
> `1 轮→赶尽杀绝 · 10 轮 0% 猜疑→以牙还牙 · 5–15%→给两次机会 · 20%→记仇/给两次机会混战 · ≥25%→赶尽杀绝 · 50%→随机`

图表用 dataviz 技能验过的暗色分类盘前六色，**顺序不能动**——相邻对的色觉分辨度
是按那个顺序过的检查；我试过按游戏配色重排，CVD ΔE 掉到 4.8，直接 FAIL。
六条序列一律配图例，颜色不单独承担身份。

**落点在最后一幕**：1300 他签了字，1302 同一套规矩赶走他，1315 他拒绝赦免。
然后他写了《地狱》——**那是一个只有一轮的世界**。判决下了就不再改，没有下一次
交手，没有回来的路。而地狱最底下一层不是杀人不是暴力，是背叛，是把信任毁掉的人；
那一层是冻住的，什么都不会再变。
> 地狱 = 抽掉了「重复交手」的佛罗伦萨。这是整关的论点。
> 落点：1295 步入政坛——他还没签过任何字，先让他看懂这台机器。素材成本：零。

## 人物登记表 `src/data/<line>/cast.json`

一个人只写一次，现实场景和《神曲》场景共用一份，防止两边写岔。
`inferno_placement` 的卡片和 `comedy_encounter` 的名牌上都有按钮，随时能调出来看。

条目结构：`name / latin / years / role / portrait / life[] / withDante[]`

**唯一的硬规矩：`life` 和 `withDante` 只写「活着的时候」。**
他后来被但丁放进哪一界、出现在第几歌，属于答案，不许写进登记表。
玩家要靠推理，不是靠读到答案——生平给的是**判断的材料**，不是判断本身。

举例：卜尼法斯的条目写禧年献金堆成小山、写《一圣通谕》、写阿纳尼之辱，
玩家自己就能推到「买卖圣职」；但整条目里不出现「地狱第十九歌」五个字。
贝雅特丽切的条目写到 1290 年她二十四岁去世为止，一个字不提她后来成了向导。

`inferno_placement` 的弹层底部直接给三界按钮——**读完当场就能放**，
不用关掉弹层再回去找卡片。决定紧跟在阅读之后，中间不隔一次操作。

四个新类型都是 **commit → contrast**：玩家先产出，提交后「你 / 实际」并列，不打 ✗。

- `silence_choice` **不显示倒计时、也不说「别动」**——要玩家自己发现手停下来句子会落。进场 5 秒内不落，给读题时间。
- `coin_market` 的提示「会不会是同一样东西」**吵到第二轮才出现**——先让玩家自己撞墙。
- `link_match` 计分只奖励「敢连」，不按连对几条给（同 predict_reveal 的理由）。

### 试玩反馈（2026-09-27）：手先动，字后读

第一版五幕里，「摸黑」「磨墙」被说好玩，「书落水池（选择题）」「沉默作答（点选项+计时）」「四人争葡萄（连线）」被说无聊。
差别不在题目难不难，在**玩家的手在做什么**：前三个是在读文字按钮，后两个是手在世界里做事（举灯、擦墙）。
改版后三个也都换成了身体动作：拖书出水、停手不动、拿银币去买。

规则：**每个小游戏的主操作应该是一个动作（拖、擦、举、停、买），而不是点一个写满字的按钮；文字判断放在动作之后。**
predict_reveal / evidence_select 这类纯文本动词仍然有用，但一个事件里不要只有它们。
- `dark_explore` 的机制就是寓言本身：玩家手里的烛光和屋里那些人一样小，是把几个片面说法并排放才猜到整体的。
- `scratch_reveal` 的「磨」不教东西，**必须带 question/options**，lint 才把它记在「先判断」。

**暂缓的**（记录理由，免得来回讨论）
- 「三界 = 三种 interaction grammar」：方向漂亮，但它预设玩家在《神曲》里待很久；
  现在《神曲》是每关末尾两分钟的一段。先当作**写作约束**用（地狱关用归类动词、
  炼狱关用变化动词、天堂关用连接动词），不做成三套规则系统。
- `chain_compose`（terza rima）：中译不承载韵，只教 ABA BCB 的形状是在教一个空壳。
- `guide_handoff` 做 scaffold fading：全线现在只有三处《神曲》遭遇，重复次数不够，fading 感觉不出来。
- 删掉现有 61 道 quiz：先别删。等新动词在几个事件上验证过，再逐个事件替换。
